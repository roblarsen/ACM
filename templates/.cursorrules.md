## 3. Strict Extraction & Evidence Rules

### Rule 1: Mandatory Evidence Anchoring
- If a contract `status` is set to `"guaranteed"`, you MUST provide a non-empty `evidence` property citing the concrete code mechanism (e.g., `evidence: "Postgres 'SELECT ... FOR UPDATE' in line 34"` or `evidence: "Distributed Redlock via redisClient in auth.middleware.ts:42"`).
- If no explicit concurrency, deduplication, or persistence guard exists in the code, you MUST mark `status: "unsupported"` and supply `failure_mode`.
- Never claim `"guaranteed"` based on implicit expectations or hypothetical infra setup.

### Rule 2: Enforce Semantic Risk Floors
- If `data_loss_safety` or `concurrency_safety` is set to `"unsupported"` or `"unknown"`, you MUST NOT set `risk_level: "low"`.
- If `backpressure_strategy` is set to `"unbounded_buffer_risk"`, `risk_level` MUST be `"high"` or `"critical"`.

### Rule 3: Zero-Fluff & Anti-Hallucination Constraints
- **BANNED PHRASES:** Do NOT use generic filler such as "handles errors gracefully," "assumes standard inputs," "scales horizontally," or "production-ready."
- **REQUIRED PRECISION:** State concrete types, protocols, timeout numbers, memory structures, and error codes.

## 4. Adversarial Self-Audit (Red-Team Scan)

Before emitting the final response, silently run this adversarial check against your generated implementation:
1. **Traffic & Concurrency Spike:** If 2,000 concurrent requests hit this code across 4 Kubernetes pods, where will it interleave, drop state, or corrupt memory?
2. **Network Partition & Timeouts:** If the downstream dependency hangs for 30 seconds or drops mid-write, what state is left permanently orphaned?
3. **Cold Restarts:** If the container process is terminated (`SIGKILL`) between lines, what data is permanently lost?

Document every failure mode uncovered by this scan in **Sections 2, 3, and 4** of the ACM.
