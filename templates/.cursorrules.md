### 1. Invariants & Data Model Boundaries
* **Payload & Validation:** [e.g., Assumes input is pre-sanitized by middleware; payload < 2MB]
* **Temporal Semantics:** [e.g., Assumes timestamps are strict UTC ISO 8601; ignores client clock skew]
* **Identity & Duplication:** [e.g., Non-unique external IDs will overwrite existing records]

### 2. State & Runtime Topology
* **Memory & Persistence:** [e.g., In-memory Map; resets on process restart; unshared across replicas]
* **Concurrency & Race Conditions:** [e.g., No mutex or distributed lock; concurrent writes will interleave]
* **Clustering & Scaling:** [e.g., Single-node only; not safe for multi-pod Kubernetes deployment]

### 3. Environmental & Network Assumptions
* **Downstream Latency & Timeouts:** [e.g., Assumes downstream API responds within 1000ms; no fallback]
* **Delivery Guarantees:** [e.g., At-least-once queue delivery will trigger duplicate processing]
* **Atomicity Across Boundaries:** [e.g., Non-transactional; DB commit succeeds even if cache update fails]

### 4. Explicit Non-Goals & Unhandled Failure Modes
* **Unhandled Failure Modes:** [e.g., Database connection pool exhaustion causes hard HTTP 500]
* **Degradation Behavior:** [e.g., Fails closed; does not serve stale data if upstream service drops]
* **Compensating Transactions:** [e.g., No rollback or Saga pattern implemented for partial failures]

## Extraction Rules & Anti-Patterns

### 1. No Fluff or Generic Statements
- **DO NOT WRITE:** "Assumes valid inputs" or "Assumes network is reliable."
- **DO WRITE:** "Assumes `userId` matches UUIDv4; null values cause an unhandled runtime rejection."

### 2. Expose the "Happy Path" Debt
Critique your own implementation under stress. Explicitly ask:
- **Scale:** What happens if 5,000 instances run this concurrently?
- **State:** Does this code hold local state in heap memory that breaks under horizontal auto-scaling?
- **Network:** What happens if the third-party dependency times out after 30 seconds?
- **Persistence:** If the server crashes on line 42 (between DB write and message publish), what state is left corrupted?

### 3. Contract Honesty
If you did not write row-locking or distributed locking logic, you MUST set `concurrency_safe: false`. Never claim safety contracts that are not explicitly implemented and tested in the code.
